# Sweet & Sweat | 캐릭터와 운동 퀘스트를 연결한 운동 습관 형성 앱

운동 습관 형성이 필요한 초보자를 위해 루틴 설정, AI 캐릭터와의 대화, 운동 퀘스트, 보상과 경쟁을 하나의 흐름으로 연결한 모바일 서비스임.

React Native 앱의 모든 화면을 구현하고, Health Connect 건강 데이터 연동과 모바일 기능·API 연동 테스트를 담당함.

## 1. 사용자 활동 분석과 요구사항 구체화

### 운동 기록을 다음 행동으로 연결하는 흐름 설계

기획 단계에서 기존 운동 관리 서비스가 기록 저장과 통계 제공에 집중하는 경우가 많다는 점에 주목함. 사용자가 걸음 수나 운동 시간을 확인하더라도, 오늘 어떤 운동을 해야 하는지와 운동 후 어떤 보상을 얻는지는 별도로 판단해야 한다고 보았음.

이를 바탕으로 운동 계획을 오늘 수행할 작은 목표로 나누고, 수행 결과를 캐릭터 스토리와 보상에 연결하는 서비스를 구상함. 본인은 캐릭터 챗 서비스에 대한 관심을 바탕으로 캐릭터·세계관·대화형 AI를 활용하는 프로젝트를 제안하고, 운동이라는 주제와 결합함.

요구사항은 팀 회의, Planfit 앱의 추천·운동 상세·루틴 화면 벤치마킹, 중간 발표 피드백을 통해 구체화함.

## 2. 핵심 문제 해결

아래 내용은 커밋의 변경 전후 코드와 보고서의 개발·검증 기록을 근거로 정리함. 개별 오류의 당시 재현 로그가 없는 경우, 코드에서 확인되는 원인과 구현 결과까지만 서술함.

### 2-1. 배틀 조회 시 최신 운동 기록이 반영되도록 동기화 시점 조정

#### 2-1-1. 문제 정의 및 원인 파악

배틀은 건강 데이터와 퀘스트 수행량을 기준으로 기록을 비교하는 기능임. 사용자가 운동한 뒤 배틀에 진입했을 때 최신 기록이 서버에 전달되지 않으면, 앱에서 확인하는 점수와 실제 수행 기록 사이에 차이가 생길 수 있음.

기존 앱은 배틀 매칭·상세 조회에서 `syncHealthDataWithServerIfStale()`을 호출함. 건강 데이터 동기화 서비스는 마지막 동기화 후 기본 30분이 지나지 않았으면 재동기화를 생략하는 구조였음. 이 간격 안에 새 운동 기록이 생기더라도 배틀 조회 전에 다시 전송되지 않을 수 있음을 변경 전 코드에서 확인함.

#### 2-1-2. 해결 과정

기존의 동기화 간격을 사용하는 경로에 더해, 배틀에서 최신 기록이 필요한 시점에 강제 동기화를 수행하도록 변경함.

| 처리 시점 | 변경 내용 |
| --- | --- |
| 매칭 요청 전 | `syncHealthDataWithServer({ force: true })` 호출 후 매칭을 요청하도록 변경함 |
| 상세 조회 | 서버 응답의 `healthSync.recommended`가 참이면 강제 동기화 후 배틀 정보를 다시 조회하도록 변경함 |
| 결과 조회 전 | 강제 동기화 후 결과 API를 호출하도록 변경함 |
| 기록 표시 | 본인과 상대의 최근 건강 데이터 반영 시각을 표시하고, 시각 정보가 없으면 기록 반영 대기 상태를 표시함 |

본인은 모바일의 API 호출 순서와 화면 표시를 수정함. 서버의 점수 산정·결과 확정 로직은 백엔드 담당자의 영역임.

#### 2-1-3. 결과

매칭과 결과 확인 전에 최신 기록을 전송하는 경로를 추가하고, 상세 화면에서는 서버가 동기화를 권장할 때 기록 전송과 재조회를 수행하도록 구현함. 사용자가 기록 반영 시각을 확인할 수 있도록 표시를 추가함.

동기화 실패 시에는 로그를 남기고 배틀 조회를 계속하는 처리가 있으므로, 모든 환경에서 최신 데이터 반영을 보장한 결과로 서술하지 않음.

근거: [배틀 건강 데이터 반영 시점 수정 커밋](https://github.com/sweetnsweat/mobile/commit/6125ab045521b9ba833c7d837b9f6609015619e1), [건강 데이터 동기화 서비스](https://github.com/sweetnsweat/mobile/blob/375cbfe/src/services/HealthConnectService.ts)를 참고함.

### 2-2. 대화 기록을 다시 열었을 때 캐릭터 이미지가 누락되는 문제 수정

#### 2-2-1. 문제 정의 및 원인 파악

캐릭터 대화는 사용자가 이전 기록을 다시 열어 스토리를 이어가는 기능임. 텍스트가 복원되더라도 캐릭터 이미지가 표시되지 않으면 신규 대화와 재진입 화면의 경험이 달라짐.

수정 전 코드에서 대화 기록을 화면 메시지로 변환할 때 캐릭터 이미지 정보를 복원하지 않는 구조를 확인함. 또한 공통 이미지 컴포넌트는 로딩 실패 후 오류 상태를 유지해, 이미지 URL이 바뀌어도 다시 로딩하지 않는 구조였음.

#### 2-2-2. 해결 과정

대화 기록 복원과 공통 이미지 컴포넌트의 상태 처리를 함께 수정함.

1. 기록의 `character_image_url`, `image_url`, `imageUrl`을 확인해 복원 메시지에 이미지 정보를 포함함.
2. 상대 경로를 이미지 서버 주소와 결합하고, 기록에서 캐릭터 이름과 이미지를 복원하도록 변경함.
3. 기록에 정보가 부족한 경우 채팅방 조회 API에서 대표 캐릭터 또는 첫 캐릭터의 이미지·이름·소개를 가져와 빈 항목을 보완함.
4. `ImageWithFallback`에서 URL이 변경되면 오류 상태를 초기화하도록 수정함.

이미지 한 필드만 추가하는 데서 끝내지 않고, 기록 데이터의 누락과 이미지 컴포넌트의 실패 상태를 함께 처리함.

#### 2-2-3. 결과

대화 기록을 복원할 때 이미지 정보를 유지하고, 부족한 캐릭터 정보는 별도 조회로 보완하는 경로를 구현함. 이미지 URL이 변경되면 이전 로딩 실패 상태에서 다시 이미지를 표시할 수 있도록 수정함.

근거: [히스토리 조회 시 캐릭터 이미지 오류 수정 커밋](https://github.com/sweetnsweat/mobile/commit/e65288a957b7cc59a3c7824604ddee0f29810441)을 참고함.

### 2-3. 스토리 퀘스트의 응답 필드와 화면 표시 기준 일치

#### 2-3-1. 문제 정의 및 원인 파악

스토리 안에서 운동 퀘스트가 발생하면 사용자는 운동 종목·목표와 스토리상 수행 이유를 확인해야 함. 앱이 응답 데이터와 다른 필드를 참조하면 제목이 기본 문구로 표시되거나 운동 목표가 화면에서 누락될 수 있음.

수정 전 화면은 `title`, `description`, `targetValue`, `targetMetric` 등을 참조함. 수정 커밋에서는 스토리 퀘스트 데이터의 `quest_name`, `mission_text`, `exercise_name`, `target`, `story_reason`을 사용하도록 변경한 내용을 확인함.

#### 2-3-2. 해결 과정

스토리 퀘스트 응답에 맞춰 화면의 데이터 매핑과 표시 항목을 변경함.

| 화면 항목 | 적용한 응답 필드 |
| --- | --- |
| 퀘스트 제목 | `quest_name`을 표시함 |
| 미션 안내 | `mission_text`를 표시함 |
| 운동 종목 | `exercise_name`을 표시함 |
| 수행 목표 | `target`을 표시함 |
| 스토리와의 연결 이유 | `story_reason`을 표시함 |

운동 퀘스트 ID가 전달되는 경우 기존 대화 선택지를 비우고 활성 퀘스트를 설정하도록 변경함. 운동 수행 단계와 일반 대화 선택 단계의 화면 상태를 구분하는 처리를 적용함.

#### 2-3-3. 결과

스토리 퀘스트의 제목·운동·목표·수행 이유를 응답 필드에 맞춰 표시하도록 구현함. 사용자가 스토리 안에서 제시된 운동과 다음 수행 목표를 함께 확인할 수 있는 화면으로 변경함.

| FastAPI·LangChain·LangGraph·OpenAI API | AI 담당자가 캐릭터 스토리·대화·선택지·퀘스트 생성과 진행 상태를 구현함. 본인은 앱의 대화·퀘스트 표시와 기록 복원 흐름을 구현함 |

## 5. 성과 및 발표 피드백

### 구현으로 연결한 사용자 활동

아래 내용은 구현한 기능이 제공하는 활동 흐름을 정리한 것이며, 실제 사용자의 운동 지속률이나 참여도 향상을 측정한 결과는 아님.

| 추가·개선한 기능 | 사용자가 수행할 수 있게 된 활동 |
| --- | --- |
| 온보딩·루틴·컨디션 입력 | 운동 경험과 선호 운동을 입력하고, 기본 루틴 선택 또는 직접 생성한 루틴을 오늘 수행할 운동과 연결함 |
| 캐릭터 대화와 운동 퀘스트 | 스토리를 진행하면서 운동 종목·목표·수행 이유를 확인하고 퀘스트를 수행함 |
| 건강 데이터 연동 | 기기에 기록된 운동 데이터를 앱에서 읽어 퀘스트·배틀 검증에 활용하는 흐름을 제공함 |
| 보상·상점·마이페이지 | 수행 후 보상과 성장 정보를 확인하고, 재화를 사용하거나 보유 요소를 조회함 |
| 배틀·랭킹 | 다른 사용자와 기록을 비교하고 결과를 확인함. 배틀 화면에 기록 반영 시각을 표시함 |
| 대화 기록 복원 | 기존 대화와 캐릭터 정보를 복원해 스토리를 이어갈 수 있도록 함 |
| 푸시 알림 | 사용자가 알림 권한과 수신 설정을 조절하고, 알림을 통해 관련 화면으로 진입하는 흐름을 제공함 |

팀 전체 결과로 앱·백엔드·AI 서버를 연결한 서비스를 구현함. 본인은 모든 모바일 화면과 건강 데이터·알림 연동, 앱 기능 및 API 테스트를 담당함. 상점 API 연결 등 모바일 저장소에도 팀원의 기여가 포함되어 있어 전체 연동을 단독 수행한 결과로 기재하지 않음.

### 중간 발표 피드백 반영

중간 발표에서 루틴·퀘스트·캐릭터 스토리·보상 사이의 연결이 더 명확해야 한다는 의견을 받음. 팀은 사용자 시나리오를 고정하고 퀘스트 완료 직후 경험치·배지가 지급되는 흐름을 우선 구현하기로 함. 본인은 앱에서 해당 흐름의 화면 연결과 데이터 표시를 점검함.

배포 후 현재 운영은 중단된 상태임. 실제 이용자 수, 운동 지속률, 만족도 등 정량 성과와 별도의 서비스 사용자 피드백은 확인된 자료에 없어 성과 수치로 제시하지 않음.

## 6. 실행과 빌드

### 실행 환경과 필수 설정

| 항목 | 확인된 설정 |
| --- | --- |
| Node.js | `package.json`에서 22.11.0 이상을 요구함 |
| Android | Android Studio 기반 개발 환경을 사용함. Gradle 설정은 최소 SDK 26, 컴파일·대상 SDK 36임 |
| 건강 데이터 | Health Connect 지원 환경과 읽기 권한이 필요함. 실제 건강 데이터 연동 검증은 Android 실기기 기준으로 수행함 |
| API 연결 | `src/config/api.ts`에서 백엔드 API와 AI 이미지 서버 주소를 설정함. Tailscale 기반 개발 서버를 공유했으며 현재 운영은 중단됨 |
| 알림 | Android Firebase 설정과 서버의 발송 설정이 필요함. Android 13 이상 알림 권한 요청을 코드에 포함함 |

### 저장소 문서에 명시된 Android 실행 명령

[Android FCM 연동 가이드](https://github.com/sweetnsweat/mobile/blob/375cbfe/docs/FCM_ANDROID_FRONTEND_GUIDE.md)에 Firebase 패키지 설치 후 Android 빌드를 다시 실행하는 명령이 명시되어 있음.

```bash
npm run android
```

이 명령은 `package.json`의 `react-native run-android` 스크립트에 연결됨. 현재 서버 운영 중단으로 당시와 동일한 서비스 사용 환경을 제공하지 않음.

자동 테스트·린트 스크립트는 저장소에 정의되어 있으나, 실행 성공 기록이 없어 통과한 검증 명령으로 제시하지 않음. 릴리스 빌드·배포 명령 역시 확인된 자료에 없어 임의로 추가하지 않음.
